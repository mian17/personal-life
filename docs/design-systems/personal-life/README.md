# Personal Life — design-system base

The Open Design design-system base for `personal-life`. Additive documentation: no repo file is imported, changed or reformatted, and nothing here is invented — it is read off the code at commit `1b7b4c5`.

- `code/` — normalised import snapshot: `index.json` (path, size, language, imports per file), `components.json` (the `@life/ui` primitives with props and variant unions), `routes.json` (Next.js App Router model with evidence), `tokens.json` (declared custom properties plus every literal outside the token file), `meta.json` (recorded commit).
- `token-map/` — crosswalk from repo tokens to `--ds-*` names, one file per family (colors, typography, spacing, radius, shadow, motion); each row carries the value, its declaration site, its usage sites and its contrast pair. `unmatched.json` records what the repo lacks and what an agent must not invent.
- `DESIGN.md` — the prose base: theme, palette, type, rhythm, radii, motion, component stylings, icons, states, responsive behaviour, accessibility, agent prompt guide.
- `preview.html` — one self-contained file, no build step; open it in a browser to see the dark palette, type and spacing scales, radii and shadow specimens, and the vendored primitives.
- `open-design.json` — the plugin manifest that points Open Design at this package.

`code/` and `token-map/` were generated by a throwaway walk of the tree (deleted after the run; no path was typed by hand). Regenerate them when `tokens.css`, `theme.css`, the primitives or the routes change: the recorded SHA is what says the snapshot still matches the code, and a token that moves without a regeneration makes every claim in `DESIGN.md` stale.

## Token contract (Open Design `TOKEN_SCHEMA`)

- `tokens.css` — the contract custom-property set, dark-first: `--bg`, `--surface`, `--fg`, `--muted`, `--accent`, `--text-*`, `--space-*`, `--radius-*`, `--elev-*`, `--motion-*`, `--container-*`. Every value is the repo's own and names its declaring line in a trailing comment. Contract slots the repo genuinely lacks (`--surface-warm`, `--fg-2`, `--meta`, `--border-soft`, `--font-display`, `--font-mono`, `--text-4xl`, `--space-6`, the three `--section-y-*`, the three `--container-gutter-*`, `--radius-sm`, `--elev-ring`, `--focus-ring`, `--accent-hover`, `--accent-active`) are aliases to a real sibling token or a derivation of the repo accent — never a new value. The light palette is `:root[data-theme='light']`, mirroring the repo's own switch.
- `design-tokens.json` — `od-design-tokens/v1`: one row per property with resolved value, role, evidence (`file:line`) and status (`source-backed` or `aliased`), plus the layer and summary counts and the recorded worktree SHA. Its token set and order are exactly the property set and order of `tokens.css`.
- `components.html` — self-contained specimen page (inline CSS, no CDN, no external font, no build step) rendering those same values: palette with role labels and hex, type and spacing scales, radii, the single shadow, motion, and the primitives — buttons, icon button, FAB, field, switch, tabs, list rows in default/dense/in-progress/due-soon/done treatments, chips and filter pill, alert, toast, dialog shell, light-theme strip.

Regeneration: edit `packages/ui/src/styles/tokens.css` (or `theme.css` / `base.css`), then re-derive all three files from it in one pass — `tokens.css` first, `design-tokens.json` second, `components.html` third — and re-record `source.gitSha` in `design-tokens.json`. A token that moves without all three moving makes this package contradict the code.
